# Building Alfred Pennyworth

A complete, no-prior-experience-assumed guide to turning this source code into a
working Audio Unit plugin that loads inside Logic Pro.

This is long on purpose. If you've never compiled a macOS app before, follow it
top to bottom and you'll end up with a working plugin. If you're experienced,
skip to [§5 The Short Version](#5-the-short-version).

## 1. What you're actually building

Audio Unit (AU) plugins on macOS come in a specific shape. You don't build a
single "plugin file" directly. Instead:

- You build a **container macOS app** (`AlfredPennyworth.app`).
- Embedded *inside* that app is an **app extension** (`.appex`) — that extension
  **is** the actual Audio Unit.
- When you run the container app even once, macOS reads the embedded extension
  and registers the Audio Unit system-wide. From then on, Logic Pro (and any
  other AU host — GarageBand, MainStage, Ableton in AU mode) can see it.

So the flow is: **source code → Xcode build → `AlfredPennyworth.app` → run it once
→ plugin appears in Logic.**

The plugin itself is an **AUv3 Generator** (`type = aurg`). A generator produces
audio rather than processing an input. Alfred Pennyworth's job: take your text or
C++ prompt, send it to your private Studio web app, wait for Suno to render a
track, download it, and play it back through Logic's audio engine so you can
record it onto a track.

## 2. Requirements & costs

| Thing | Required? | Cost | Notes |
|-------|-----------|------|-------|
| A Mac | Yes | — | Apple Silicon or Intel, macOS 12 (Monterey) or newer |
| Xcode 15+ | Yes | Free | From the Mac App Store |
| Apple ID | Yes | Free | You almost certainly already have one |
| Apple Developer Program | **No, for personal use** | $99/yr | Only needed to *distribute* the plugin to other people (notarization). For building and running on *your own* Mac, a free Apple ID works. |
| Homebrew | Optional | Free | `setup.sh` will fall back to a direct download if you don't have it |
| Logic Pro | To actually use it | $199 | GarageBand (free) also works and is a fine test host |
| Your deployed Studio web app | Yes, to generate | — | The Vercel URL + password from the earlier steps |

**Key point on the $99:** You do **not** need to pay Apple anything to build this
and use it yourself. A free Apple ID lets Xcode sign the app for your own
machine. You only need the paid Developer Program if you want to send the built
plugin to someone else's Mac without Gatekeeper blocking it. See
[§11](#11-signing-notarization--sharing-the-plugin).

## 3. Installing the prerequisites

### 3a. Xcode

1. Open the **App Store** on your Mac.
2. Search for **Xcode**.
3. Click **Get / Install**. It's large (~7 GB+) and takes a while.
4. Once installed, **open Xcode at least once** and let it install any
   "additional required components" it prompts for. Agree to the license.

> You can also install Xcode from <https://developer.apple.com/xcode/> if the
> App Store is being slow.

### 3b. Command-line tools

Open **Terminal** (Applications → Utilities → Terminal) and run:

```bash
xcode-select --install
```

If they're already installed you'll see a message saying so — that's fine. If a
dialog appears, click **Install** and wait for it to finish.

Verify:

```bash
xcode-select -p
# should print something like: /Applications/Xcode.app/Contents/Developer
```

### 3c. Homebrew (optional but recommended)

This project is generated by a tool called **XcodeGen**, which reads
`project.yml` and produces the `.xcodeproj`. The easiest way to install XcodeGen
is via Homebrew.

`setup.sh` will **automatically download a standalone XcodeGen** if you don't
have Homebrew, so this step is optional. But if you want Homebrew anyway:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Follow the prompts. When it finishes, it may tell you to run a couple of
`echo >> ~/.zprofile` commands to add `brew` to your PATH — do those if so.

Verify:

```bash
brew --version
```

## 4. Building the plugin, step by step

From here on, "the folder" means the unzipped `alfred-pennyworth` directory.

### 4a. Generate the Xcode project

Open Terminal and `cd` into the folder. For example, if you unzipped it to your
Downloads:

```bash
cd ~/Downloads/alfred-pennyworth
```

Make the setup script executable and run it:

```bash
chmod +x setup.sh
./setup.sh
```

What this does:

- Checks that Xcode command-line tools are present.
- Finds or installs XcodeGen (Homebrew → Mint → standalone download, in that
  order).
- Runs `xcodegen generate`, which reads `project.yml` and creates
  **`AlfredPennyworth.xcodeproj`** next to it.

When it's done you'll see:

```
==> Done. Open AlfredPennyworth.xcodeproj in Xcode.
```

### 4b. Open it and set your signing team

```bash
open AlfredPennyworth.xcodeproj
```

Xcode launches. Now you need to tell it *who* is signing the build. This is the
one manual step that can't be scripted, because it's tied to your Apple ID.

1. In the left sidebar (the **Project navigator**, the folder icon), click the
   blue **AlfredPennyworth** project at the very top.
2. The editor shows a list of **TARGETS**. There are two:
   - `AlfredPennyworthApp`
   - `AlfredPennyworthExtension`
3. Select **AlfredPennyworthApp**, then click the **Signing & Capabilities** tab.
4. Check **Automatically manage signing**.
5. In the **Team** dropdown, choose your name / Apple ID.
   - If the dropdown is empty, click it → **Add an Account…**, sign in with your
     Apple ID, then come back and select it.
6. Now select the **AlfredPennyworthExtension** target and repeat steps 3–5 with
   the **same team**.

> **Bundle identifier clashes:** The default IDs are `com.studio.alfredpennyworth`
> and `com.studio.alfredpennyworth.extension`. With a free Apple ID these usually
> work, but if Xcode complains that the bundle ID is unavailable, change the
> prefix to something unique to you — e.g. `com.yourname.alfredpennyworth` and
> `com.yourname.alfredpennyworth.extension`. Edit both targets, keeping the
> `.extension` suffix on the extension.

### 4c. Build

1. At the top of the Xcode window, find the **scheme selector** (next to the
   run ▶ / stop ■ buttons). Make sure the scheme is **AlfredPennyworthApp** and
   the destination is **My Mac**.
2. Press **⌘B** (Product → Build).
3. Wait. The first build compiles everything; subsequent builds are faster.
4. A green checkmark / "Build Succeeded" means you're good. If you get red
   errors, jump to [§9 Troubleshooting](#9-troubleshooting).

### 4d. Register the plugin

The plugin is registered with macOS when the container app runs. Easiest way:

- Press **⌘R** (Product → Run) in Xcode. The **Alfred Pennyworth** window appears
  with usage instructions. That single launch is enough — macOS has now scanned
  the embedded Audio Unit.
- You can quit the app afterward; the registration sticks.

To confirm macOS sees it, run in Terminal:

```bash
auval -a | grep -i alfred
```

You should see a line containing `Alfred Pennyworth: Studio`. To run Apple's full
validation on it:

```bash
auval -v aurg alfp STDO
```

(`aurg` = generator, `alfp` = subtype, `STDO` = manufacturer — these come from
the extension's `Info.plist`.) A passing `auval` means Logic will accept it.

## 5. The short version

For people who've done this before:

```bash
cd alfred-pennyworth
./setup.sh                       # installs XcodeGen if needed, runs xcodegen generate
open AlfredPennyworth.xcodeproj
# Set Team on both targets in Signing & Capabilities
# ⌘B to build, ⌘R to run once (registers the AU)
auval -v aurg alfp STDO          # optional: validate
```

Then open Logic → AU Generators → Alfred Pennyworth: Studio.

## 6. Using it in Logic Pro

1. Open **Logic Pro**. (If Logic was already open during the build, quit and
   reopen it so it rescans plugins. You can also force a rescan in
   **Logic Pro → Settings → Plug-in Manager → Reset & Rescan Selection**.)
2. Create a new track: **Track → New Software Instrument Track**.
3. On that track's channel strip, click the **Instrument** slot.
4. Choose **AU Generators → STUDIO (or "Alfred Pennyworth") → Alfred Pennyworth:
   Studio**.
5. The plugin window opens — the dark purple **ALFRED PENNYWORTH** UI.

> If you don't see it under AU Generators, it usually means either the app
> hasn't been run yet (do [§4d](#4d-register-the-plugin)) or `auval` is failing
> (see [§9](#9-troubleshooting)).

## 7. Connecting it to your Studio web app

The plugin is just a front-end; the actual generation happens on your deployed
Studio web app (the Vercel URL from earlier).

1. In the plugin window, click the **⚙ gear icon** (top right).
2. Enter:
   - **Studio URL** — e.g. `https://your-studio-app.vercel.app` (no trailing
     slash needed; it's stripped automatically).
   - **Password** — the `PRIVATE_PASSWORD` you set when you deployed.
3. Click **Save**.

These are stored in macOS `UserDefaults` on your machine only, and persist across
Logic restarts. They're only ever sent to the Studio URL you entered.

Now:

- Pick **Text Prompt** or **C++ Directive** mode.
- Optionally hit a **preset** (East Coast Underground, Post-Hardcore Shoegaze,
  Synthwave Noir, Jazz Fusion) to fill the style field.
- Type your prompt, set a title if you like, and click **GENERATE**.
- The status line walks through: Submitting → Generating (up to ~2 min) →
  Downloading → Ready.

## 8. How recording the audio works

Alfred Pennyworth plays the generated track through Logic's audio engine on the
instrument track it's loaded on. To capture it as actual audio you can edit:

**Option A — Bounce in place / record onto an audio track**

1. After the status says **Ready**, create an **Audio track** and set its input
   to the instrument track's output (or use **Track → Bounce-in-Place**).
2. Arm the audio track for recording.
3. Press **R** (record) in Logic, then click **REPLAY** in the plugin so the
   track plays from the start.
4. Stop when it finishes. You now have a recorded region.

**Option B — Bounce the project**

If the plugin track is the only thing playing, **File → Bounce → Project or
Section** will render whatever the plugin outputs.

> The **VOL** slider in the plugin controls playback gain feeding Logic, so set
> it before recording. **REPLAY** restarts playback from the top, which is the
> moment to hit record.

**Save to Library:** the **SAVE** button posts the finished track's metadata back
to your Studio web app's `/api/library`, so it also shows up in the web app's
Library page.

## 9. Troubleshooting

**`setup.sh` fails: "Xcode command-line tools not found"**
Run `xcode-select --install`, install Xcode from the App Store, open Xcode once
to finish component installation, then re-run `./setup.sh`.

**`xcodegen: command not found` even after Homebrew**
Your shell may not have `brew` on its PATH yet. Close and reopen Terminal, or
run `eval "$(/opt/homebrew/bin/brew shellenv)"`. Then `brew install xcodegen`.
Or just let `setup.sh` use its standalone-download fallback.

**Xcode: "Signing for 'AlfredPennyworthApp' requires a development team"**
You skipped [§4b](#4b-open-it-and-set-your-signing-team). Set the Team on
**both** targets.

**Xcode: "Failed to register bundle identifier"**
The default bundle ID is taken. Change the prefix to something unique
(`com.yourname.…`) on both targets, keeping `.extension` on the extension.

**Build error mentioning `vDSP` or `Accelerate`**
The extension links `Accelerate.framework` (declared in `project.yml`). If you
hand-edited the project, make sure that framework is still linked under the
extension target's **Build Phases → Link Binary With Libraries**.

**Plugin doesn't appear in Logic**
1. Did you **run** the app once ([§4d](#4d-register-the-plugin))? Building alone
   isn't enough.
2. Run `auval -v aurg alfp STDO`. If it fails, the failure message tells you why
   (most often a signing/entitlement issue).
3. In Logic: **Settings → Plug-in Manager**, find Alfred Pennyworth, and click
   **Reset & Rescan Selection**. If it's marked as failed validation there,
   Logic shows the reason.

**"Studio URL not configured" error when generating**
Open ⚙ and make sure both the URL and password are filled and you clicked Save.

**Generation times out after 2 minutes**
Suno occasionally takes longer under load, or the web app couldn't reach Suno.
Check that your Studio web app works in a browser with the same prompt, and that
its `SUNO_API_KEY` is valid.

**Audio plays at the wrong pitch / speed**
This shouldn't happen — the plugin resamples Suno's audio to Logic's sample rate
automatically. If it does, file it as a bug; note your Logic sample rate
(**Settings → Audio → Sample Rate**).

**No sound at all but status says "Playing"**
Make sure the instrument track isn't muted, the plugin **VOL** slider isn't at
0%, and the track's output is routed to your monitoring output.

## 10. Project layout reference

```
alfred-pennyworth/
├── BUILD.md                        ← this file
├── setup.sh                        ← generates the Xcode project
├── project.yml                     ← XcodeGen spec (targets, frameworks, signing)
│
├── Shared/                         ← compiled into BOTH targets
│   ├── Models.swift                ← request/response data types, GenerationMode
│   ├── StudioAPIClient.swift       ← talks to your Studio web app (login/generate/poll/save)
│   └── AudioDownloader.swift       ← downloads Suno MP3, decodes to PCM
│
├── AlfredPennyworthApp/            ← the container macOS app
│   ├── AppDelegate.swift
│   ├── MainViewController.swift    ← the instructions window you see when you run it
│   ├── Info.plist
│   └── AlfredPennyworthApp.entitlements   ← sandbox + network client
│
└── AlfredPennyworthExtension/      ← the actual Audio Unit (.appex)
    ├── AlfredPennyworthAU.swift           ← AUAudioUnit: real-time render block, resampling, gain
    ├── AlfredPennyworthViewController.swift ← AUViewController + factory; hosts the SwiftUI UI
    ├── ContentView.swift                  ← the plugin's SwiftUI interface
    ├── PluginViewModel.swift              ← state + the generate/poll/replay/save logic
    ├── Info.plist                         ← registers type=aurg subtype=alfp manufacturer=STDO
    └── AlfredPennyworthExtension.entitlements
```

**Audio Component identity** (from the extension `Info.plist`) — useful for
`auval` and for any host that asks:

| Field | Value |
|-------|-------|
| type | `aurg` (generator) |
| subtype | `alfp` |
| manufacturer | `STDO` |
| name | `Alfred Pennyworth: Studio` |

## 11. Signing, notarization & sharing the plugin

Everything above gets you a plugin that runs **on the Mac you built it on**, with
a free Apple ID. That's all most people need.

If you want to give the built plugin to **someone else** so they can drop it in
without Xcode:

1. You need the **Apple Developer Program** ($99/yr) for a "Developer ID
   Application" certificate.
2. Build the app with that Developer ID certificate (Release configuration).
3. **Notarize** it with Apple:
   ```bash
   xcrun notarytool submit AlfredPennyworth.app.zip \
     --apple-id "you@example.com" --team-id "YOURTEAMID" \
     --password "app-specific-password" --wait
   xcrun stapler staple AlfredPennyworth.app
   ```
4. The recipient runs the app once to register the AU, exactly like you did.

Without notarization, another person's Mac will block the app with a Gatekeeper
warning ("can't be opened because Apple cannot check it for malicious software").
They *can* override it (right-click → Open, or System Settings → Privacy &
Security → Open Anyway), but notarization is the clean path for sharing.

For your own personal use in Logic, you can ignore this entire section.
